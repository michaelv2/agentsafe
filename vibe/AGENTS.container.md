
## In this container (AgentSafe)
- You're in a throwaway AgentSafe container. The user's projects are at `/workspace/projects` (on the host they're `/home/maqo/projects`, so translate that path in skills and docs). All are readable; only the ones the user named at launch are writable. To write to another project, ask the user to relaunch with it.
- There's no direnv here. Any project environment variables the user set up are already in your environment; don't source `.envrc` or `.env` files.
- Secrets are hidden on purpose: `.env` and `.envrc` files, keys and credentials files are empty, and some folders (e.g. `agentsafe/config`, `agentsafe/data`) are empty. The user's home directory and the local network are out of reach too, except llm-server's Ollama for local subagents such as `coder`. Don't try to get around any of this.
- Python: the project's own `.venv` was built on the host and won't run here. Use this container's: `"$(agentsafe-venv)/bin/python"`, and install into it with `"$(agentsafe-venv)/bin/pip" install ...` (after the user approves, as above). It's kept between sessions.
- Before installing, adding or upgrading any package (pip, npm, or any other package manager), review each one first and report what you found: is it the real, well-known project and not a look-alike name; does that exact version exist and is it current; are there known vulnerabilities in it (check OSV or GitHub advisories); does installing it run build or post-install scripts; is it well established or brand new. Pin exact versions, and for pip prefer `--only-binary=:all:` so no setup code runs. Install only after the user approves your findings. If you can't verify a package, don't install it: tell the user and ask. This is a blocking step, not something to do in parallel with the install.
- Git: commit, but don't push. There are no GitHub credentials here; the user reviews and pushes from the host.
- `~/.vibe/.env` holds your own API key. Never read or print it.
